## Executive verdict

Verity's local profile is real and well engineered: the full Python/static suite is green, its
Docker controls were exercised against a live daemon, cached and API behavior work, the two
GitHub repositories are public, and real filed Issues exist. The system's strongest claim—when
execution fails, leave the reproduced value empty—is backed by both tests and artifacts.

The repository was not, however, in the state its current documents claimed. The preserved
eight-source run contains seven completed verdicts and one failed Whisper job, the documented
demo startup command writes directly to a protected fixture and therefore aborts, the timing
“contradiction” lacks comparable conditions, and the Cloud Run sandbox is neither live-tested
nor safe for untrusted production execution. The overall rating is:

- **Local MVP:** ready for review/demo after the final interactive browser pass.
- **Evidence quality:** strong failure discipline, incomplete condition provenance.
- **Google Cloud at audit time:** unsafe prototype; subsequently replaced and deployed.
- **Hackathon “done” bar at audit time:** unmet; subsequently passed with live unseen sources.

## Scope and methods

The audit inspected the application, agent, storage, queue, sandbox, deployment, frontend,
tests, documentation, Git state, public GitHub state, Docker daemon/images, locked environment,
cached artifacts, and preserved live SQLite runs. It ran static checks, the full ordinary and
Docker suites, the standalone eight-probe isolation script, local HTTP smoke tests, and focused
regressions added for every safe correction.

The in-app Browser reported zero attached surfaces. No claim of fresh visual/click testing is
made; that remaining step is listed explicitly.

## Findings and disposition

### Critical / release-blocking

| Finding | Disposition |
|---|---|
| Cloud sandbox executes arbitrary code with outbound networking under a Firestore-capable service identity; metadata credentials are reachable | **Resolved:** replaced by the credential-free handoff and no-role sandbox; six sensitive APIs denied the stolen metadata token live |
| Sandbox image selected default local settings and opened SQLite instead of the Firestore handoff; its minimal requirements could not import the eager agent package | **Resolved:** explicit Firestore handoff, lazy agent imports, minimal sandbox image, and live nested execution proof |
| API service account blueprint lacks Vertex `roles/aiplatform.user` | **Resolved:** the trusted application identity has the required Vertex role; the sandbox remains no-role |
| Pub/Sub secret is embedded in the push URL while the configured OIDC identity is not validated by the app; the whole service is public | Open: split/validate an OIDC worker boundary and remove the URL secret |
| PowerShell deployment can continue after native command failures, writes secrets with a trailing newline, can capture service-account describe output into an email variable, and may print success after partial failure | Contained by the early deployment guard; replace the blueprint with checked native wrappers before enabling it |
| A four-attempt pipeline can consume the entire 3600-second Cloud Run pipeline timeout, leaving no parser/debug/install/report overhead | Open: enforce a per-job deadline and smaller per-attempt budget |

### High-impact correctness and security

| Finding | Disposition |
|---|---|
| Timing result was classified `contradicted` without matching hardware/runtime conditions | **Fixed for sensitive metric classes:** new `conditions_not_comparable`; historical Issue #5 remains stale evidence |
| Failed processes could carry a parsed number into `actual_value` despite saying no value was asserted | **Fixed and regression-tested** |
| Model-provided regex could catastrophically backtrack, use the wrong capture shape, select an early metric, or emit non-finite values | **Fixed:** disposable two-second matcher, one capture, final match, finite float |
| A patch that failed exact application stayed in the cumulative bundle and poisoned every later retry; its replacement command could persist too | **Fixed and regression-tested** |
| Short-circuit artifact filing errors could be cached as completed, unlike normal report failures | **Fixed with one persistence policy** |
| Cloud/control-plane failures entered the Debug loop and could become `could_not_verify` | **Fixed:** infrastructure is a failed job, no claim verdict or wasted repair calls |
| Parser/publisher URL strings were inserted with `model_copy`, bypassing Pydantic URL validation | **Fixed:** reconstruct and validate typed models |
| Filed Issue content included untrusted source/model Markdown and mentions | **Fixed:** mention neutralization, inline escaping, and collision-safe dynamic code fences |
| GitHub README filename probe auto-followed redirects before the guarded GET loop | **Fixed:** HEAD never auto-follows; every real redirect stays in the validation loop |
| Claim/result models accepted NaN and infinity | **Fixed:** all claimed and observed scalars must be finite |
| Frontend starts an interval after a cached terminal response, polls deep links only once, and leaves failure paths inconsistent | **Fixed with one start/stop polling path** |
| Shipped SQLite fixture inspection opened in writable/WAL mode | **Fixed:** immutable read-only store and tests for no sidecars |
| Branch/HEAD retries could execute different upstream commits, and `git clone --branch <sha>` was unreliable for exact objects | **Fixed:** capture the first full commit, persist it on the job, fetch it detached, pin every retry, and fail closed on drift |
| A transient queue publication failure marked the job failed; a stranded queued job was never republished on repeat submission | **Partially fixed:** keep it queued and republish the same ID; a transactional delivery outbox is still required for automatic recovery |
| Firestore exposed a completed job and its claim-memory pointer in separate writes | **Fixed:** both writes now commit in one Firestore transaction |

### Remaining product/evidence gaps

- Verdict comparison does not yet prove observed dataset, checkpoint, fetched source bytes,
  dependency, precision, hardware, or protocol equality. Sensitive metrics are protected first;
  all metrics ultimately need explicit provenance.
- Repository-backed repair attempts now stay on the first resolved commit. The runner image is
  still selected by a mutable tag, and URL-cache results never expire or bind to source bytes.
- A claimed job has no lease/heartbeat/recovery sweep. Process death can strand it in a running
  state; Pub/Sub redelivery alone cannot reclaim it.
- Firestore job/trace payloads have no strategy for the 1 MiB document limit.
- Install-time build hooks execute with network access. The Docker boundary limits host access,
  but does not prevent scanning reachable LAN services during clone/install.
- SSRF checks validate DNS before httpx performs its own resolution, leaving a DNS-rebinding
  time-of-check/time-of-use gap.
- Transport retries inside each ADK call multiply the visible three repair attempts; there is no
  explicit per-job model-call/token budget.
- The Parser's significance judgement is model-driven and grounded by prompt, but runtime code
  does not independently verify that its quote supports the selected claim.
- The declarative `app/agent.py` graph is not executable end to end: Environment has no tool,
  Debug is unconditionally sequenced once, and Reporter cannot file. The durable runtime is
  custom Python; only Parser/Debug model calls instantiate typed ADK agents.
- CI previously excluded all Docker tests and did not build either image. It now builds the local
  and cloud images, probes the minimal cloud import, runs Docker tests, and executes the full
  isolation script.
- C: remains low on space. Docker data is on E:, but a clean conda/pip build or default temp
  workload can still exhaust C: if not directed deliberately.

## Runtime truth versus earlier documents

The preserved catalogue database has seven completed sources and one failed Whisper source.
Whisper was rejected for attempting `../venv/pip.conf`; that refusal was correct, while the old
pipeline's handling of the refusal was not. The handling is now covered by tests, but no new live
Whisper result exists.

The shipped demo cache itself is consistent—five jobs and four outcomes—but it is intentionally
write-protected. A server must use a copied database. Earlier instructions pointing uvicorn
directly at `docs/assets/demo-cache/verity-demo.db` fail by design and have been corrected.

Issues #1, #3, #4, and #5 are real report artifacts. Issue #2 is a synthetic publisher wiring
probe. Existing Issues are historical artifacts and were not edited during this audit.

## Recommended secure cloud sequence

See [NEXT-IMPLEMENTATION.md](NEXT-IMPLEMENTATION.md) for the exact evidence schema, fenced-lease
and outbox contracts, broker endpoints, UID boundary, network split, and acceptance tests.

1. Add a broker owned by the trusted API/pipeline service. Persist only a hash of a high-entropy,
   single-use run capability; expose narrowly scoped request-read and result-write operations.
2. Give the sandbox task no Firestore, Secret Manager, Vertex, Pub/Sub, Cloud Run, or project
   role. Remove the capability from process environment before executing repository code.
3. Separate networked acquisition/build from offline evaluation, or route each through tested
   policies that deny metadata/private ranges and evaluation egress.
4. Put Pub/Sub delivery behind verified Google OIDC with an exact audience and expected service
   account; do not place a secret in a query string.
5. Add leases, heartbeats, recovery, transactional outbox behavior, artifact-size offloading,
   revision/image digest capture, and a global job deadline.
6. Build both images in CI. Test import/startup, no-role identity, broker replay/expiry, metadata
   denial, egress denial, task timeouts, Firestore size behavior, and failed deployment steps.
7. Only then remove the fail-closed guards, deploy to staging, and run an unseen claim through
   Vertex, Firestore, Pub/Sub, Cloud Run Jobs, Trace/Logging, and GitHub Issue filing.
